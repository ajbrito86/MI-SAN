# Tarea: agregar sitio público mínimo de MI-SAN para requisitos de Google Play

## Objetivo

Agregar al proyecto un sitio web público estático de MI-SAN para cumplir requisitos de Google Play, especialmente:

- Página pública de eliminación de cuenta.
- Política de privacidad pública.
- Términos y condiciones públicos.
- Página de soporte básica.

Este sitio debe poder desplegarse con Docker en el VPS usando el mismo flujo de producción existente.

---

## Alcance

No tocar backend funcional de la API.
No tocar lógica mobile.
No cambiar base de datos.
No agregar CMS.
No agregar autenticación.
No complicar la arquitectura.

Debe ser un sitio estático simple, mantenible y listo para producción.

---

Política de privacidad - MI-SAN

Última actualización: 2 de julio de 2026

MI-SAN recopila datos necesarios para crear y administrar cuentas, SANes, participantes, pagos, configuraciones y soporte.

Los datos pueden incluir nombre, correo electrónico, teléfono, foto de perfil opcional, información de uso, versión de la aplicación, identificadores técnicos y diagnósticos.

Usamos esta información para operar la aplicación, proteger cuentas, mejorar el servicio, enviar avisos funcionales y cumplir requisitos legales.

MI-SAN no vende datos personales. Podemos compartir datos con proveedores de infraestructura, servicios de analítica, Google AdMob cuando aplique publicidad, servicios de autenticación, servicios de notificaciones y autoridades competentes cuando la ley lo requiera.

Los datos se transmiten usando conexiones cifradas cuando la aplicación se comunica con nuestros servicios.

Puedes solicitar la eliminación de tu cuenta y datos asociados desde la aplicación o escribiendo a support@kingdom-devs.net.

Docker

Crear Dockerfile para servir el sitio con Nginx.

Ejemplo esperado:

FROM nginx:1.27-alpine
COPY . /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80

nginx.conf debe servir archivos estáticos y permitir rutas limpias si aplica.

compose.production.yml

Agregar nuevo servicio:

public-site:
  build:
    context: ./apps/public-site
    dockerfile: Dockerfile
  container_name: mi-san-public-site
  restart: unless-stopped
  expose:
    - "80"
  networks:
    - npm_proxy

No exponer puertos públicos directamente.
Debe estar en la red npm_proxy para publicarlo con Nginx Proxy Manager.

deploy-prod.sh

Actualizar el script para que también construya y levante el sitio público.

Debe seguir usando:

docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" build
docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" up -d

Si ya construye todos los servicios, no hace falta agregar comandos especiales.

Pero sí verificar que el servicio public-site quede incluido en el compose.

Al final del deploy, mostrar un mensaje como:

Sitio público MI-SAN desplegado. Configurar dominio en Nginx Proxy Manager apuntando al contenedor mi-san-public-site puerto 80.
Dominios previstos

No configurar SSL ni dominios dentro del código.

Más adelante se configurará en Nginx Proxy Manager, por ejemplo:

mi-san.kingdom-devs.net

o:

legal.mi-san.kingdom-devs.net

La URL que usaremos en Google Play para eliminación de cuenta será algo como:

https://mi-san.kingdom-devs.net/eliminar-cuenta.html
Validaciones

Antes de terminar, ejecutar:

docker compose -f compose.production.yml --env-file apps/api/.env.production build

y confirmar que construyen:

api
public-site

También verificar que el sitio responde dentro del contenedor:

docker compose -f compose.production.yml --env-file apps/api/.env.production up -d public-site
docker compose -f compose.production.yml --env-file apps/api/.env.production exec public-site wget -qO- http://localhost/eliminar-cuenta.html
