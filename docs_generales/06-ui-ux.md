# UI/UX - Mi-San

## Objetivo

Diseñar una experiencia simple, confiable y familiar para usuarios de todos los niveles tecnológicos.

La aplicación debe sentirse:

- Cercana.
- Segura.
- Moderna.
- Fácil de usar.
- Dominica y culturalmente familiar.

---

# Principios de Diseño

1. Mobile First.
2. Menos clics, mejor experiencia.
3. Información importante siempre visible.
4. Priorizar claridad sobre sofisticación.
5. El usuario debe saber siempre qué debe hacer.

---

# Estilo Visual

## Apariencia

- Moderna.
- Limpia.
- Minimalista.
- Profesional.

Evitar:

- Exceso de colores.
- Pantallas saturadas.
- Formularios largos.

---

# Paleta Sugerida

## Primario

Verde.

Representa:

- Dinero.
- Ahorro.
- Crecimiento.
- Confianza.

## Secundario

Azul.

Representa:

- Seguridad.
- Estabilidad.

## Estados

Éxito: Verde.

Pendiente: Amarillo.

Advertencia: Naranja.

Error: Rojo.

Información: Azul.

---

# Navegación Principal

Bottom Tabs:

- Inicio.
- Mis Sociedades.
- Notificaciones.
- Perfil.

Máximo:

4 tabs.

---

# Home

Debe responder rápidamente:

- ¿Cuánto debo?
- ¿Cuándo debo pagar?
- ¿Cuándo cobro?
- ¿Tengo pagos pendientes?

Widgets:

- Próximo pago.
- Próximo cobro.
- Sociedades activas.
- Alertas.
- Actividad reciente.

---

# Tarjetas

Toda información principal debe mostrarse mediante cards.

Ejemplo:

Sociedad:

- Nombre.
- Monto.
- Frecuencia.
- Estado.
- Próxima fecha.

---

# Estados Visuales

Usar badges grandes.

Ejemplo:

PENDIENTE

CONFIRMADO

ATRASADO

INCUMPLIDO

Los estados deben ser identificables incluso sin leer el texto.

---

# Tipografía

Utilizar fuentes claras.

Recomendación:

- Inter.
- Nunito.

Evitar fuentes decorativas.

---

# Iconografía

Usar:

lucide-react-native

Iconos:

- Dinero.
- Calendario.
- Notificaciones.
- Usuarios.
- Historial.

---

# Experiencia del Organizador

Las acciones críticas deben estar agrupadas:

- Confirmar pagos.
- Invitar participantes.
- Generar turnos.
- Crear ciclo.

---

# Experiencia del Participante

Mostrar siempre:

- Próximo pago.
- Historial.
- Turno asignado.
- Monto pendiente.

---

# Empty States

Todas las pantallas deben contemplar estados vacíos.

Ejemplo:

"No perteneces a ninguna sociedad todavía."

---

# Loading States

Toda carga debe mostrar skeletons.

Nunca dejar pantallas en blanco.

---

# Confirmaciones

Acciones críticas requieren confirmación:

- Expulsar participante.
- Cerrar sociedad.
- Eliminar evidencia.
- Finalizar ciclo.

---

# Accesibilidad

- Tamaños de fuente adecuados.
- Botones grandes.
- Contraste suficiente.
- Áreas táctiles cómodas.

---

# Publicidad

Los anuncios deben ser discretos.

Nunca interrumpir:

- Registro de pagos.
- Confirmación de pagos.
- Inicio de sesión.

---

# Regla General

El usuario debe poder aprender a usar la aplicación sin entrenamiento previo.
