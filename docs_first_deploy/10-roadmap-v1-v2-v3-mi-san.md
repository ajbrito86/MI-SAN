# 10 - Roadmap V1 V2 V3 - MI-SAN

## Objetivo

Definir claramente qué funcionalidades pertenecen a cada versión para evitar retrasar innecesariamente el lanzamiento comercial.

Principio rector:

**Hecho y publicado es mejor que perfecto y nunca publicado.**

---

# V1 - Primera versión comercial (MVP)

Objetivo:

Publicar la aplicación y validar el mercado real.

## Funcionalidades obligatorias

### Autenticación

- Registro.
- Login.
- Recuperación de contraseña.
- Edición de perfil.

### Gestión de SANes

- Crear SAN.
- Editar SAN.
- Invitar participantes.
- Agregar miembros.
- Ver detalle SAN.

### Gestión financiera

- Registrar pagos.
- Registrar cuotas.
- Historial de pagos.
- Estado de pagos por participante.

### Organización

- Notificaciones básicas.
- Historial de movimientos.
- Dashboard principal.

### Monetización

- Trial Premium 45 días.
- AdMob.
- Compra Premium sin anuncios.

### Legal

- Política privacidad.
- Eliminar cuenta.
- Términos y condiciones.

## NO entra en V1

- Chat interno.
- Exportaciones avanzadas.
- Multi idioma.
- Integraciones bancarias.
- IA.
- Reportería avanzada.

---

# V2 - Optimización y crecimiento

Objetivo:

Mejorar experiencia de usuario y aumentar retención.

## Funcionalidades

- Exportar PDF.
- Exportar Excel.
- Filtros avanzados.
- Recordatorios inteligentes.
- Mejoras UX/UI.
- Tutorial interactivo.

## Monetización

- Nuevas funcionalidades Premium.
- Métricas comerciales avanzadas.

---

# V3 - Escalamiento

Objetivo:

Convertir MI-SAN en la referencia regional.

## Funcionalidades

- Múltiples SAN por organizador.
- Roles avanzados.
- Copias de seguridad automáticas.
- Sincronización multi dispositivo.
- Compartir reportes.
- Dashboard administrativo web.

---

# Deuda técnica permitida

Se acepta posponer:

- Optimizaciones menores.
- Refactors no críticos.
- Mejoras visuales menores.

No se acepta posponer:

- Seguridad.
- Estabilidad.
- Pérdida de datos.
- Errores críticos.

---

# Criterios para cerrar V1

La V1 estará cerrada cuando:

✅ La aplicación esté publicada.

✅ Existan usuarios reales utilizándola.

✅ No existan errores críticos.

✅ La monetización esté funcionando.

---

# Regla oficial del proyecto

Antes de agregar una nueva funcionalidad preguntar:

"¿Esta funcionalidad es imprescindible para publicar?"

Si la respuesta es NO:

Mover automáticamente a V2 o V3.
